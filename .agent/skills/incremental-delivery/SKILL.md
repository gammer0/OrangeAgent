# 增量交付与自检

## 三条铁律

1. **一次只做一件事**：一个工具调用只写一个文件，或只改一个概念。
2. **改完立刻验证**：写完 `.py` 就用 `/tool/code/py/check`；跑得动就用
   `/tool/code/py/run_brief`（≤20 秒、无交互）。
3. **不猜错误**：工具报错时先读返回的完整信息，再决定是改参数、改文件还是换工具。

## 推荐节奏

```
列目录/读已有文件  →  写 config.py  →  语法检查
写 game.py         →  语法检查      →  无头自检（200 步）
写 main.py         →  语法检查      →  短运行（喂 q 退出）
写 README.md       →  结构验收（snake/check）
```

## 失败处理

| 现象 | 处理 |
|---|---|
| 语法错误 | 按 `行:列` 精确改，不要整文件重写 |
| 超时 | 缩小范围重试；检查是否有 `while True` 无退出条件 |
| 自检 `ok:false` | 读 `reason` 字段，缺什么补什么（类名/方法名） |
| 重复同一错误 2 次 | 停下来换思路，不要第三次原样重试 |

## 不要做的事

- 不要在没读文件的情况下假设内容。
- 不要把整段代码贴给用户当交付；文件写进磁盘才算完成。
- 不要为通过检查而删检查点（例如把断言注释掉）。
