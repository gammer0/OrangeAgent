# 水位跳过与类型化压缩记录

> 日期：2026-10-18　前置：`docs/07-C3压缩接线修复记录.md`

## 1. 问题：水位被整段跳过

### 现象

```
单步 40% -> 90%：normal -> session_end     ← 两个压缩点全部跳过
单步增长 16000：session_end（从头到尾没压过）
```

### 根因

`_decide()` 中收尾判断**排在最前且直接返回**：

```python
if ratio >= SESSION_END:          # ≥85%
    return JudgeResult(action="session_end", ...)   # 压缩机会被吃掉
```

因此只要单步跨过 85%，50% / 75% 两个压缩点从未被评估。

### 修复

判定顺序改为：`0.75 → 0.50 → session_end`。

收尾退到最后，且只在**压缩水位已耗尽**时触发。压缩后若仍超 85%，
下一轮会依次消耗剩余水位，最终收敛到收尾，不会无限循环。

修复后：

```
单步 40% -> 90%：compress_2 -> compress_1 -> session_end -> session_end
```

## 2. 语义变更（需明确）

| 项 | 旧 | 新 |
|---|---|---|
| `session_end` 优先级 | 最高 | 最低 |
| ≥85% 是否压缩 | 否 | 有水位的未压缩记录时，先压 |
| 收尾时机 | 首次达到 85% | 压缩水位耗尽后 |

**理由**：旧语义假设水位渐进爬升，但实测单步可从 40% 跳到 90%。
这个假设不成立，因此"85% 不压缩"的承诺本身就成了压缩失效的原因。

受影响测试共 5 个，均已改为：
- 需要观测收尾的，显式调用 `mark_compressed(50)` / `(75)` 把水位标记为已耗尽
- 新增 `test_high_water_yields_to_pending_compress` 固化新行为

## 3. 类型化压缩（按用户要求）

压缩规则不再由模型自由发挥，而是由**系统提示词按消息类型逐条规定**。

### 各类型的压缩方法

| 标记 | 来源 | 压缩规则 |
|---|---|---|
| `[user]` | 用户指令 | **逐条保留**原始意图，不得改写措辞；约束、路径、命名、禁止项逐字保留 |
| `[assistant:call <路径>]` | 工具调用 | 只留有效调用与意图；同路径反复调用合并并注明次数（如 `read main.py ×3`）；参数内容一律丢弃 |
| `[tool:<路径>]` | 工具结果 | **只留结论不留原文**：写文件→`已写入 <路径>（N 字符）`；读文件→`读取 <路径>（M 行）`；执行→`退出码 N` + 一行关键输出（失败必须保留错误类型与位置）；被截断的标注`（原输出已截断）` |
| `[assistant]` | 无工具调用的模型文本 | 只留**决定**与**对用户的承诺**，过程性描述与寒暄全删 |

### 输出格式固定为五节

```
## 目标      ## 已完成      ## 关键决定      ## 待处理     ## 环境坑
```

硬约束：总长 ≤ 输入字符数的 15%；信息不足写"无"，不得编造。


## 4. 顺带修复：分块压缩不再丢数据

原实现 `text[:24000]` 硬截断，**超出部分静默丢失**——这是压缩最不可接受的失败方式。

改为按 `SUMMARY_INPUT_CHARS` 切块，逐块压缩，再合并一次：

```
len(text) <= 24000  → 单次调用
否则                → N 次分段调用 + 1 次合并调用（递归直至收敛）
```

分块预算扣减 80 字符头部余量，避免拼接后轻微超限。

## 6. 仍未覆盖

- 压缩后若实际估算值未下降（摘要过长），会继续消耗下一个水位，直至收尾；
  目前靠"每水位只触发一次"兜底，没有"摘要质量不达标就重试"的机制。
- 类型化规则只在真实模型上人工验证，未做自动化断言（模型输出非确定性）。
