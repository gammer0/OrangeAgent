# 安装与使用指南

> 面向**拿到这个项目的人**。从零开始到跑起界面，约 3 分钟。
> 下面每一步都经过实际验证。

---

## 一、三种安装方式，选一种

### 方式 A：从 whl 安装（推荐，最干净）

需要先拿到构建产物 `harness-0.1.0-py3-none-any.whl`（约 190 KB）。

**前置条件**：Python ≥ 3.12，以及 [uv](https://docs.astral.sh/uv/)（没装的话：`pip install uv`）

```bash
# 1. 安装为全局命令
uv tool install harness-0.1.0-py3-none-any.whl

# 2. 验证
harness --help
```

装完后 `harness` 就是一个独立命令，与项目目录无关。

### 方式 B：从源码安装（要改代码时用）

```bash
git clone <仓库地址> harness
cd harness

# 开发模式：改代码立即生效
uv sync

# 或装成全局命令
uv tool install .
```

### 方式 C：不安装，直接在项目里跑

```bash
uv sync
uv run python -m harness.cli serve
```

## 二、首次配置（必做，约 1 分钟）

### 1. 准备一个工作目录

这个目录就是 agent 的「项目根」，它能读写的文件都在这里。

```bash
mkdir myproject
cd myproject
```

### 2. 生成配置文件

```bash
harness config init
```

会生成 `.env`：

```ini
DEEPSEEK_API_KEY=sk-your-key-here     ← 改这一行
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
...
```

### 3. 填入 API 密钥

去 <https://platform.deepseek.com/api_keys> 申请，替换掉 `sk-your-key-here`。

> 用别的 OpenAI 兼容服务（Moonshot、本地 vLLM 等）也可以：改 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 即可。

### 4. 校验

```bash
harness config check
```

期望输出：

```
配置有效
  base_url = https://api.deepseek.com
  model = deepseek-chat
  api_key = sk-e...54b8        ← 只显示首尾，不会泄露完整密钥
  temperature = 0.7
```

**这一步失败不要往下走。** 常见原因：

| 提示 | 原因 |
|---|---|
| `环境变量 DEEPSEEK_API_KEY 仍是模板占位符` | 忘了改 `.env` 里的 `sk-your-key-here` |
| `缺少 DEEPSEEK_API_KEY` | 没有 `.env`，或不在同一目录 |
| `配置无效: ...` | 密钥格式不对或被撤销 |

## 三、启动

```bash
harness serve
```

输出：

```
Harness 控制台：http://127.0.0.1:8012
工作目录：C:\Users\you\myproject
按 Ctrl+C 停止
```

浏览器打开 **<http://127.0.0.1:8012>**。

常用参数：

```bash
harness serve --port 9000          # 换端口
harness serve --host 0.0.0.0       # 允许局域网访问（注意：无鉴权）
harness serve --reload             # 改代码自动重载（开发用）
```

## 四、第一次对话

1. 点右上角 **新建会话**
2. 在底部输入框打字，按 **Ctrl+Enter** 发送
3. 观察三处变化：
   - 中间对话区：文字逐字出现（流式）
   - 右侧「轨迹」：出现 `STATE` / `ASSISTANT` / `TOOL` 事件
   - 顶部状态灯：推理时变橙色呼吸，结束变回绿色

**第一次可能看不到工具调用**。让它读文件就会触发：

```
读取 pyproject.toml 的内容
```

此时右侧会出现 `/tool` → `/tool/os` → `/tool/os/file` → `/tool/os/file/read` 的完整下钻路径。

## 五、验证安装是否完整

```bash
# 组件自检（出问题先跑这个）
harness service doctor

# 看工具树
harness service tree

# 看超参数
harness config show
```

`service doctor` 会逐项检查并给修复建议，任何一项失败都有明确提示。

## 六、目录与文件在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| **配置文件** | `<工作目录>/.env` | 密钥在这里，不要提交到 git |
| **超参数覆盖** | `~/.OAgent/settings.json` | 设置界面写的，只存与默认值不同的项 |
| **能力清单** | `~/.OAgent/capabilities.json` | 工具/skill/MCP 的注册表 |
| **权限** | `~/.OAgent/permissions.json` | 路径级允许/拒绝 |
| **会话数据** | `~/.OAgent/harness.db` | SQLite，含消息与轨迹 |
| **工作记忆** | `<工作目录>/WORK.md` | agent 自己维护的笔记 |
| **技能包** | `~/.OAgent/skills/` | |

> `~/.OAgent` 可用环境变量 `HARNESS_HOME` 改到别处。

## 七、常见问题

**`harness: command not found`**

`uv tool install` 之后没刷新 PATH。重开终端，或检查 `~/.local/bin` 是否在 PATH 中。

**端口被占用**

```bash
harness serve --port 8013
```

**界面能打开但提示「无法连接」**

服务进程已退出。看终端是否有报错；常见是工作目录下没有 `.env`。

**界面空白或样式错乱**

强制刷新（`Ctrl+F5`）。若仍空白，检查浏览器控制台，通常是静态资源未随包安装——重装一次即可。

**`config init` 说文件已存在**

用 `--force` 覆盖，或手动编辑现有 `.env`。

**想换模型**

顶部下拉框只影响**新建会话**。已有会话用 `harness` 之外的 API：

```bash
curl -X PATCH http://127.0.0.1:8012/api/sessions/<会话ID> \
  -H "Content-Type: application/json" -d '{"model":"deepseek-reasoner"}'
```

**改了超参数不生效**

设置界面会明确标出「重启生效」的项，那些需要重启 `harness serve`。

## 八、卸载

```bash
uv tool uninstall harness                # 移除命令
rm -rf ~/.OAgent                         # 移除数据（会话、配置、密钥）
```
