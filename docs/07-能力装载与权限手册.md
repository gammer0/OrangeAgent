# 工具 / Skill / MCP 加载与权限设置 —— 操作手册

> 设计说明见 `06-工具分组与外来能力.md`；本文只讲怎么用。

## 一、三类能力装在同一个工具树上

```
/tool                          内置工具根
  /tool/os/file/read           ← 内置（白名单）
  /tool/math/calc              ← 外来工具（你提供代码）
/mcp                           外部服务根
  /mcp/filesystem/read_file    ← MCP 服务器暴露的工具
/skill                         skill 根
  /skill/fluid-particle-sim    ← skill 直接加载
```

**路径 = 分组结构**。`/tool/math/calc` 里的 `math` 就是分组，不需要额外注册。

## 二、分组

```bash
harness groups list                            # 列出全部分组（含成员数）
harness groups create tool/math --description "数学工具"
harness groups remove tool/math                # 有成员时拒绝
harness groups remove tool/math --force        # 强制删描述
```

### 分组什么时候会出现在工具树索引里

**只有写了描述的分组才会出现。**

原因：无描述的中间节点只是把子工具路径的公共前缀重复一遍，不提供任何
新信息，是纯噪音。实测 17 个工具时，12 行分组行**全部**是纯占位，占索引
体积 12%，而收益为零。

```
# 没有描述时——分组被省略，只剩叶子
/tool
/tool/fluid/check — 流体仿真结构验收：文件/API/不依赖 pygame
/tool/fluid/probe — 流体物理验收：跑 N 步查守恒/边界/静置
/tool/os/file/read — 按行读取工作目录内文本文件

# 给 tool/fluid 加上描述后——它才出现
/tool
/tool/fluid — 流体仿真验收
/tool/fluid/check — 流体仿真结构验收：文件/API/不依赖 pygame
/tool/fluid/probe — 流体物理验收：跑 N 步查守恒/边界/静置
```

这条规则是个**激励设计**：想让分组出现在模型眼前，就得说明它是干什么的。
分组因此承载真实信息，而不是当纯结构占位。

L1 资源根（`/tool`、`/skill`、`/mcp`）是例外，恒定出现——它们标出三类
能力的边界。

### 什么时候需要显式创建分组

1. 想给它一句**描述**（让它出现在索引里）；
2. 想**先建好挂载点**，稍后再装工具。

否则直接在路径里用新段即可，分组会自动派生（只是不会出现在索引里）。

## 三、内置工具

```bash
harness tools list --available                 # 看可选内置工具与预设
harness tools add /tool/os/file/read
harness tools add --preset files
harness tools remove /tool/os/file/read
```

## 四、外来工具（你提供的代码）

**安全立场**：harness 允许执行工具本体代码，来源安全由供应链（你）保证。不做沙箱。

### 4.1 写工具本体

一个普通 Python 文件，约定函数签名为 `run(**kwargs) -> str`：

```python
# ext/calc.py

def run(a: float = 0, b: float = 0, workdir: str = ".") -> str:
    """a + b。声明 workdir 参数即可拿到当前工作目录。"""
    return f"{a}+{b}={a + b}"
```

- 函数名可自定义（用 `--callable` 指定），缺省 `run`。
- 声明了 `workdir` 参数（或 `**kwargs`）时，harness 自动注入。
- 返回值会作为工具结果字符串回灌给模型。

### 4.2 装载

```bash
harness tools add-ext /tool/math/calc \
    --target ./ext/calc.py \
    --callable run \
    --description "加法计算" \
    --caps read \
    --idempotent
```

| 参数 | 说明 |
|---|---|
| `path` | 工具在树上的路径，中间段即分组 |
| `--target` | 脚本路径（相对工作目录）或模块名（如 `mypkg.tools.calc`） |
| `--callable` | 函数名，默认 `run` |
| `--description` | 单行描述，写进工具树索引 |
| `--caps` | 能力位：`read` / `write` / `exec` / `net`，可重复；缺省 `exec` |
| `--idempotent` | 标记幂等（并发调度用） |
| `--schema` | 参数 JSON Schema 文件路径；省略则为空对象 |

**装载时就校验脚本存在**。若目标缺失，该条会被跳过并记录原因，不会拖垮其他工具。

## 五、MCP 服务器

按标准 MCP 协议（JSON-RPC 2.0 over stdio）连接。

```bash
# 添加：会立即拉起进程、完成握手、拉取工具清单
harness mcp add filesystem \
    --command "npx" \
    --arg "-y" \
    --arg "@modelcontextprotocol/server-filesystem" \
    --arg "."

harness mcp list
harness mcp remove filesystem          # 连带删除其工具条目
```

**服务器名 = 分组名**。上面的命令会在 `/mcp/filesystem/` 下挂载该服务器暴露的所有工具。

带环境变量：

```bash
harness mcp add myserver --command "python" --arg "server.py" --env API_KEY=xxx --env MODE=prod
```

调用时按需 spawn 子进程、握手、调用、关闭。工具清单在 `add` 时快照进能力清单，因此运行时不需要为「发现工具」而常驻进程。

## 六、Skill

```bash
harness skills add ./SKILL.md --name foo --description "用途"
harness skills add ./SKILL.md --name bar --group skill/research   # 挂到分组下
harness skills list
harness skills show foo                  # 打印 SKILL.md
harness skills remove foo
```

support 本地文件、内置模板、http(s) URL。`--force` 可覆盖已存在内容。

## 七、权限设置（真实屏蔽）

### 7.1 模型

- **默认允许**：没有记录 = 允许（B15）。所以只需记录「拒绝」。
- **精确匹配**：键必须是完整绝对路径，如 `/tool/os/shell/run`。
- **祖先生效**：拒绝 `/tool/math` 会隐藏整棵子树（`/tool/math/calc` 一并消失）。
- **两个作用域**：`local`（CLI / 服务组合根）与 `web`（Web 会话）。

### 7.2 命令

```bash
# 查看某路径的实际判定
harness perms show /tool/os/shell/run
#   路径: /tool/os/shell/run
#     [local] 允许 — 默认允许（B15）
#     [web]   允许 — 默认允许（B15）

# 拒绝（同时作用于 local 与 web）
harness perms deny /tool/os/shell/run

# 只拒绝 Web 侧
harness perms deny /tool/os/shell/run --agent web

# 拒绝整个分组及其子树
harness perms deny /tool/fluid

# 恢复允许
harness perms grant /tool/os/shell/run

# 列出所有拒绝记录
harness perms list
```

### 7.3 屏蔽效果

拒绝之后，两件事同时发生：

1. **查询不可见**——`service tree`、Web 的 `/api/tools`、注入模型的工具索引里都不再出现该路径。
2. **调用被拒**——`tree.resolve()` 抛 `PermissionDenied`，返回错误码 **`3a`**。

实测：

```
$ harness perms deny /tool/fluid
已拒绝: /tool/fluid（agent: local, web）

$ harness service tree
/tool
/tool/code
/tool/game
/tool/os
...
# /tool/fluid 及其子工具全部消失
```

### 7.4 存储位置

`.agent/permissions.json`

```json
{
  "version": 1,
  "agents": {
    "local": {"grants": {}},
    "web": {"grants": {"/tool/os/shell/run": false}}
  }
}
```

文件损坏时降级为「全部允许」并在启动时记录原因——不支持「损坏即全禁」，否则配置写坏会导致服务完全不可用。

## 八、常见任务速查

| 目标 | 命令 |
|---|---|
| 看看现在有哪些工具 | `harness tools list` 或 `harness service tree` |
| 装一个自己的工具 | `harness tools add-ext /tool/x/y --target ./x.py` |
| 接一个外部 MCP 服务 | `harness mcp add <名> --command <cmd> --arg ...` |
| 禁用危险工具 | `harness perms deny /tool/os/shell/run` |
| 禁用整个分组 | `harness perms deny /tool/fluid` |
| 只禁用 Web 侧 | `harness perms deny <path> --agent web` |
| 检查某路径是否可用 | `harness perms show <path>` |
| 排查清单问题 | `harness service doctor`（problems 会列出被跳过的条目） |
