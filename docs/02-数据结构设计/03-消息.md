# 消息（A 组）

> 返回 [总览](README.md)

---

## 3.1 类型层次

```
Message (ABC)
├── SystemMsg
├── UserMsg
├── AssistantMsg
└── ToolMsg

ToolCall (独立值对象)
```

## 3.2 字段定义

```
SystemMsg
├── content: str                        必填，装配产物
└── 约束：会话中仅一条，且必须是 messages[0]

UserMsg
├── content: str                        必填，不得为空串
└── 约束：见 A9

AssistantMsg
├── content: str | None                 有 tool_calls 时可为 None
├── tool_calls: list[ToolCall]          空列表表示最终答案
└── is_final: bool                      派生只读，恒等于 tool_calls == []

ToolMsg
├── tool_call_id: str                   必填，必须匹配某个 ToolCall.id
├── name: str                           内部字段，工具树路径；不投影给 provider
└── content: str                        必填，不可为 None / dict / list

ToolCall
├── id: str                             必填，provider 返回的调用 id
├── name: str                           必填，完整绝对路径，必以 / 开头（如 /os/file/read）
└── arguments: str                      必填，原始 JSON 字符串，不提前解析
```

## 3.3 `SystemMsg` 的组成

`content` 由五段按**固定顺序**拼接而成：

| # | 段 | 来源 | 内容 |
|---|----|------|------|
| 1 | **系统要求** | 代码内常量 | 系统提示词：LLM 响应必须执行的工作，含响应格式定义，以及工作记忆的工作模式说明 |
| 2 | **工具树索引** | `ToolTree` | `tree_index(depth=2)`，默认 L2（资源层 + 任务组层），仅路径 + 一行描述 |
| 3 | **长期记忆引用** | `MemoryStore` | 长期记忆文件名（`MEMORY.md`，全系统唯一），**不含路径与正文** |
| 4 | **角色与行为准则** | 代码内常量 | 身份定位、语气、边界约束 |
| 5 | **会话上下文** | `Session` | 工作目录 + 工作记忆相对路径 |

拼接方式：

```
content = [1] + "\n\n" + [2] + "\n\n" + [3] + "\n\n" + [4] + "\n\n" + [5]
```

| # | 约束 |
|---|------|
| A0a | 五段顺序固定，分隔符固定为 `"\n\n"`，拼接结果在会话内逐字节不变 |
| A0b | 工作记忆**正文不进** `SystemMsg`；第 1 段只说明“存在一个共享工作记忆文件、何时读写” |
| A0c | 第 3 段只列文件名，不列内容 |
| A0d | 第 5 段放末尾；`session_id` / 租户 / 创建时间等系统标识不得进入 |
| A0e | 第 2 段索引深度默认 L2（`depth=2`），输出 L1 与 L2 两级条目 |

**工作记忆的工作模式**（写入第 1 段）：项目中创建一个共享文件作为**项目工作记忆**，agent 在必要时写入或读取；读写结果以 `ToolMsg` 返回，不回写 `messages[0]`。

## 3.4 约束

| # | 约束 | 校验时机 |
|---|------|---------|
| A1 | `messages[0]` 必须是 `SystemMsg` | 装配时 |
| A2 | `ToolMsg.tool_call_id` 必须能匹配前序 `AssistantMsg.tool_calls` 中某一项 | 写入时 |
| A3 | `AssistantMsg.tool_calls` 非空时，其后必须存在等量 `ToolMsg` | 调用下一轮 LLM 前 |
| A4 | `ToolMsg.content` 必须是 `str` | 构造时（类型保证） |
| A5 | `ToolCall.arguments` 必须是合法 JSON 或显式记录解析失败 | Dispatcher 执行前（详见 [参数校验](09-参数校验.md)） |
| A6 | `ToolMsg.name` 必须与对应 `ToolCall.name` 逐字符相同 | 写入时 |
| A7 | `AssistantMsg.content` 与 `tool_calls` 不得同时为空 | 构造时 |
| A8 | `is_final` 为派生只读属性，不得在构造时传入，恒等于 `len(tool_calls) == 0` | 构造时 |
| A9 | `UserMsg.content` 不得为空串 | 构造时 / `Inbox` 入队时 |
| A10 | `ToolCall.name` 必须是完整绝对路径（以 `/` 开头），不得为缩写或相对路径 | Dispatcher 执行前 |

## 3.5 消息校验器

所有 A 组约束收敛到一个唯一入口：

```
validate_messages(messages: list[Message]) -> None
违反任一约束 → 抛 MessageInvariantError(rule="A3", detail="...")
```

| 调用点 | 检查的约束 |
|--------|-----------|
| 每次调用 LLM 前 | A1、A2、A3、A10 |
| C3 压缩重建后 | A1、A2、A3 |
| 组间补占位后 | A2、A3 |

约束必须在构造函数中执行的（A7、A8、A9）不重复放入校验器；校验器只负责**跨消息的序列级约束**。

## 3.6 序列化投影

```
to_provider(messages: list[Message], discovered: DiscoveredTools | None = None) -> list[dict]

SystemMsg    → {"role": "system",    "content": content}
UserMsg      → {"role": "user",      "content": content}
AssistantMsg → {"role": "assistant", "content": content,
                 "tool_calls": [{"id": id, "type": "function",
                                 "function": {"name": name,
                                              "arguments": arguments}}]}
ToolMsg      → {"role": "tool",      "tool_call_id": tool_call_id,
                 "content": content}          ← `name` 不投影
```

`AssistantMsg.content` 的投影规则：

| 值 | 投影结果 |
|----|---------|
| `str`（含 `""`） | 原值 |
| `None` | `null`（不省略键） |

约束：投影不得引入任何非 provider 认识的字段。

## 3.7 已发现工具的临时注入

`discovered` 非空时，在投影结果**末尾**追加一条 `system` 消息：

```json
{"role": "system", "content": "已发现工具：\n/os/file/read — 读取文件\n..."}
```

该条仅存在于本次请求的渲染产物中，**不写入 `messages`**。

| # | 约束 |
|---|------|
| A11 | 注入项只能追加到投影结果**末尾**，不得插入中间位置 |
| A12 | 注入内容不得写入 `messages`；注入前后 `messages` 长度与内容不变 |
| A13 | 不含注入项时，投影结果必须与不传 `discovered` 时逐字节相同（保 KV cache） |
| A14 | `validate_messages` 只校验 `messages`，不校验投影产物 |
