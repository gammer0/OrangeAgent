# 会话层（H 组）

> 返回 [总览](README.md)

系统支持多会话并行运行。

---

## 2.1 字段定义

```
Session
├── session_id: str                    全局唯一，路由键
├── messages: list[Message]            会话历史
├── inbox: Inbox                       每会话独立
├── watermark: Watermark
├── tree_query: TreeQueryState         每会话独立
├── tree_version: int                  绑定的工具树快照版本
├── working_dir: str                   工作目录，进 SystemMsg 第 5 段
├── created_at: float
├── last_activity: float               最近活动时间，用于驱逐排序
└── status: "active" | "idle" | "ended"

SessionRegistry
├── sessions: dict[str, Session]       session_id → Session
├── lock: threading.Lock
└── policy: EvictionPolicy             驱逐策略

EvictionPolicy
├── max_resident: int = 20            内存中最多驻留会话数
├── idle_timeout_s: int = 1800        空闲超时后可卸载
└── sweep_interval_s: int = 60        扫描周期

SessionRecord                         持久化行（SQLite）
├── session_id / working_dir
├── created_at / updated_at / status
└── watermark: Watermark | None        序列化为 JSON
```

## 2.2 隔离边界

| 层级 | 结构 | 共享 / 隔离 |
|------|------|------------|
| 进程 | `FlatStore` / `ToolTree` | **共享**（只读） |
| 进程 | `ReverseProxy` 连接池 | **共享** |
| 进程 | `Executor` 线程池 | **共享**（每会话配额） |
| 会话 | `messages` / `Inbox` / `Watermark` / `TreeQueryState` / `DiscoveredTools` / `StepController` | **隔离** |
| 会话 | `TraceEvent` 输出文件 | **隔离**（一会话一文件） |

## 2.3 持久化

会话历史存入 SQLite。**`SystemMsg` 不入库**，恢复时按当前工具树重新装配。

**数据库**：每工作目录一个 `<workdir>/.agent/orange.db`，WAL 模式，每线程独立连接。

```sql
CREATE TABLE sessions (
    session_id   TEXT PRIMARY KEY,
    working_dir  TEXT NOT NULL,
    created_at   REAL NOT NULL,
    updated_at   REAL NOT NULL,
    status       TEXT NOT NULL,     -- active | idle | ended
    watermark    TEXT               -- JSON 序列化，可空
);

CREATE TABLE messages (
    session_id   TEXT NOT NULL,
    seq          INTEGER NOT NULL,  -- 会话内单调递增
    type         TEXT NOT NULL,     -- user | assistant | tool
    content      TEXT,              -- 可空（assistant 纯工具调用）
    tool_calls   TEXT,              -- JSON 字符串，仅 assistant
    tool_call_id TEXT,              -- 仅 tool
    name         TEXT,              -- 仅 tool，内部字段
    created_at   REAL NOT NULL,
    PRIMARY KEY (session_id, seq),
    FOREIGN KEY (session_id) REFERENCES sessions(session_id)
);
```

**事务单元**：单个 `ExecGroup`。

| 事务 | 写入内容 |
|------|---------|
| LLM 响应后 | 一条 `assistant` 记录（含 `tool_calls`） |
| 每个 `ExecGroup` 完成 | 该组全部 `tool` 记录 |
| 补占位 | 该组全部 `3e` 记录 |

同组记录必须同一事务提交，保证不会出现“部分 `ToolMsg` 已落库”的不一致状态。

**恢复流程**：

```
1. 读 sessions 行
2. SELECT messages ... ORDER BY seq
3. validate_messages(messages)
4. 重新装配 SystemMsg（当前工具树）
5. TreeQueryState.delivered 与 DiscoveredTools 置空
```

崩溃不会留下未闭合的 `tool_calls`：要么整组提交，要么整组未写。因此不需要额外的崩溃修复流程。

## 2.4 驱逐策略

`Session` 持有 `messages` / `Inbox` / `Watermark`，内存不能无限驻留。`idle` 会话可卸载，需要时从 SQLite 重建。

**状态与内存驻留**：

| `status` | 内存驻留 | 说明 |
|----------|---------|------|
| `active` | 是 | 正在跑循环，**永不卸载** |
| `idle` | 是（可卸载） | 等待用户输入 |
| `ended` | **否** | 立即从内存移除，仅存于数据库 |

**扫描与卸载**：

```
每 sweep_interval_s 秒（daemon 线程）：
  1. 持 SessionRegistry.lock
  2. 移除全部 status == "ended" 的会话
  3. 若 len(sessions) > max_resident：
       按 last_activity 升序，选择 idle 且两通道均为空的会话卸载
       直到 len(sessions) <= max_resident 或无可卸载对象
  4. 释放锁
```

**恢复**：卸载不丢数据。再次访问时从 SQLite 重建 `Session`，并置空 `TreeQueryState.delivered` 与 `DiscoveredTools`。

## 2.5 约束

| # | 约束 |
|---|------|
| H1 | 会话级结构不得跨会话共享引用 |
| H2 | `SessionRegistry` 的读写必须持锁；临界区不得包含 LLM 调用或工具执行 |
| H3 | 单会话占用的执行线程数不得超过 `MAX_WORKERS // 2`，保证至少两个会话可同时推进 |
| H4 | `session_id` / 租户 / 创建时间等系统标识不得进入 `SystemMsg` |
| H5 | `working_dir` 在会话内固定，装配进 `SystemMsg` 第 5 段 |
| H6 | `SystemMsg` 不入库；恢复时重新装配 |
| H7 | 单个 `ExecGroup` 的全部消息必须同一事务提交 |
| H8 | 恢复时 `TreeQueryState.delivered` 与 `DiscoveredTools` 置空 |
| H9 | `messages.seq` 在会话内单调递增且无空洞 |
| H10 | `active` 状态的会话永远不得卸载 |
| H11 | 卸载必须在 `SessionRegistry.lock` 内完成，且确认 `status == "idle"` 与两通道为空 |
| H12 | `ended` 会话必须立即从内存移除，只保留数据库记录 |
| H13 | 卸载仅丢弃内存对象，不得删除数据库记录 |
| H14 | 卸载后再次访问必须从 SQLite 重建，并置空 `delivered` 与 `DiscoveredTools` |
| H15 | `Session.tree_version` 在会话创建时固定；挂载只影响新会话 |
