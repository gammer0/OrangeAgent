## 7.1 字段定义

```
TraceEvent
├── session_id: str                      必填，所属会话
├── step: int
├── ts: float                            Unix 时间戳
├── kind: "llm_call" | "tool_exec" | "compress" | "inject" | "error" | "abort" | "memory_extract"
└── payload: dict
```

日志按会话分文件：一会话一 JSONL。

> **注意：系统里有两套轨迹，职责不同，不要混为一谈。**
>
> | | `harness/trace.py` → JSONL 文件 | `harness/session_store.py` → `trace_events` 表 |
> |---|---|---|
> | 位置 | `<home>/traces/<session_id>.jsonl` | `orange.db` 的 `trace_events` 表 |
> | 写入者 | 核心层 `TraceLogger`（E 组） | Web 层 `SessionRunner.persist_trace()` |
> | 粒度 | 每步一行，同步落盘（E1） | 按安全点批量刷写 |
> | 用途 | 崩溃定位、离线分析 | 前端轨迹面板回放（含树状下钻） |
>
> 前端「轨迹」面板读的是 **SQLite 表**（`GET /api/sessions/{id}/trace`），
> 因此重启后仍能看到完整的 `/tool → /tool/os → leaf` 下钻链；下钻**不会**
> 写入消息表（见 §7.4）。


## 7.2 `payload` 结构

| kind | payload 字段 |
|------|-------------|
| `llm_call` | `model` / `tokens_in` / `tokens_out` / `duration_ms` / `tool_call_count` |
| `tool_exec` | `path` / `tool_id` / `arguments` / `ok` / `error_type` / `duration_ms` |
| `compress` | `level` / `before_tokens` / `after_tokens` / `summary_chars` |
| `inject` | `channel`(`chat`/`control`) / `content_chars` |
| `error` | `error_type` / `message` / `retry_count` |
| `abort` | `reason` / `coalesced`(bool，是否因清空而丢弃) |
| `memory_extract` | `status` / `entries_added` / `duration_ms` |

## 7.3 约束

| # | 约束 |
|---|------|
| E1 | 每步结束追加一行，不缓存到最后统一写 |
| E2 | JSONL 每行必须是完整可解析的 JSON 对象 |
| E3 | 每条事件必须带 `session_id`；写入文件按会话隔离 |

## 7.4 Web 轨迹表（`trace_events`）

面向 UI 的第二套轨迹，与消息表**分离存储**：

```
trace_events
├── session_id: str      复合主键之一
├── seq: int             会话内单调递增（复合主键之一）
├── kind: str            tool | assistant | route | compress | usage | state | error | inject
├── payload: str         JSON 序列化
└── created_at: float
```

**为什么不写进 `messages` 表**

消息表是模型上下文。树状下钻（`/tool` → `/tool/os` → `/tool/os/file`）只是
临时的脚手架：一旦叶子工具被调用，它揭示的工具已进入发现缓存
（`DiscoveredTools`），下钻轮次会被 `AgentLoop._prune_resolved_descents`
立即从历史中剪除。若此时才落盘，存进去的也只是剪枝后的结果。

而用户需要知道「这个工具是怎么被找到的」，所以下钻事件改走 `trace_events`：

| 存储 | 内容 | 重启后 |
|---|---|---|
| `messages` | 干净对话（无下钻） | ✅ 恢复为模型上下文 |
| `trace_events` | 完整审计流（含下钻） | ✅ 前端轨迹面板可回放 |

**其他约束**

| # | 约束 |
|---|------|
| W1 | `(session_id, seq)` 主键，`seq` 由 `MAX(seq)+1` 续接，重启不断号 |
| W2 | `delta`（流式预览片段）**不写入**该表——一次回复数百条，只会淹没审计信息 |
| W3 | 读取前先 `persist_trace()` 冲刷缓冲，否则刚落盘的事件会漏读 |
| W4 | `GET /api/sessions/{id}/trace` 直接读表而非内存环形缓冲，避免 500 条上限截断历史 |
