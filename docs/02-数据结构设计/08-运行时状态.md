# 运行时状态（F 组）

> 返回 [总览](README.md)

## 8.1 字段定义

```
Watermark                             上下文水位记录
├── capacity: int                     模型上下文上限
├── compressed_at: set[int]           已触发压缩的水位（50 / 75）
└── last_estimate: int

JudgeResult                           水位判定结果
├── action: "normal" | "compress_1" | "compress_2" | "session_end"
└── ratio: float

RouteDecision                         Jev 路由结果
├── branch: str | None                 选中的一级分支路径
├── confidence: float                  0.0 – 1.0
└── fallback: bool                     是否回退全量
```

## 8.2 约束

| # | 约束 |
|---|------|
| F1 | `compressed_at` 只增不减，同一水位不重复加入 |
| F2 | `RouteDecision.branch == None` 时 `fallback` 必须为 `True` |

## 8.3 水位判定顺序（I5）

判定顺序是 **75% → 50% → 85%**，不是按阈值从高到低：

```
if ratio >= 0.75 and 75 not in compressed_at:  → compress_2
elif ratio >= 0.50 and 50 not in compressed_at: → compress_1
elif ratio >= 0.85:                             → session_end
else:                                            → normal
```

**收尾必须放最后**：若先判 85%，一次长工具输出从 40% 直接冲到 90% 时，
会立即判定"收尾"，两个压缩机会全部作废。先给压缩机会，压完水位下降，
下一轮再决定是否收尾。

## 8.4 判定与执行分离

`judge()` **只读状态，绝不写 `compressed_at`**（仅更新 `last_estimate`）。
写入由 `compressor.compress()` 在实际完成压缩后执行。

原因：若判定时就标记已压缩，`compress()` 会立即撞上自己的「重复触发」检查
（I5）而放弃执行，压缩永远不会发生。

## 8.5 Web 层补充状态

`SessionRunner` 中与单轮推理相关的运行时状态（不在核心 `Session` 内）：

```
_turn_started_at: float | None     本轮开始时间；None 表示无进行中的轮次
_last_progress_at: float           最近一次进展（delta 或批次完成）
turn_timeout_s: float = 300        无进展容忍时长
```

**为什么需要**：推理线程是 daemon，阻塞在网络调用上时既不会自己退出也无人
回收；而 `sweep` 只清理 `idle` 会话，卡死的会话状态是 `active`，永远轮不到。
每挂一次就永久损失一个 runner 槽位。

**判定依据用「最后进展时间」而非「轮次开始时间」**，否则正常生成数分钟的
长回答会被误杀。超时后置 `error` 状态并清空锚点，会话立即恢复可用，不必
等待那个仍阻塞的线程。
