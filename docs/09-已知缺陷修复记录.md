# 已知缺陷修复记录

> 日期：2026-10-18　分支：`fix-known-defects`

## 修复项

### 1. 单次输出上限截断了写入参数（P0）

**现象**：agent 写文件时报"写入内容过大被截断"，参数在 `_rjust(` 处断掉。

**实测根因**：`args长度 4016`，正好撞上 `LLM_MAX_TOKENS=4096`。
这是**模型输出上限**，不是 C1 截断（C1 只作用于工具返回值，
已核实 `parse_call_arguments` 不做截断）。

**修复**：`DEFAULT_MAX_TOKENS` 4096 → 8192，`.env` 同步。

### 2. 压缩空转，永远到不了收尾（P0）

**现象**：摘要质量差时，`assemble()` 卡在 `compress_1` 无限循环。

```
0: compress_2   compressed=True   msgs=6  ratio=1.34  记账=[75]
1: compress_1   compressed=True   msgs=6  ratio=1.34  记账=[75]
2: compress_1   compressed=True   msgs=6  ratio=1.34  记账=[75]   ← 无限重复
```

**根因**：`compress()` 在"记录不足以切分"时返回 `list(messages)`——
一个新的浅拷贝对象。用 `compressed_messages is not history` 判断，
**永远为 True**，于是反复报"已压缩"，但消息数从未变化。

**修复**：

1. 判定改用「长度或元素是否真的变化」：
   ```python
   actually_compressed = len(after) != len(before) or any(
       a is not b for a, b in zip(before, after, strict=False)
   )
   ```
2. **无论压缩是否生效都标记水位**。否则 `judge()` 会反复返回同一水位，
   永远推进不到 `session_end`。
3. 记账权从 `compress()` 收归 `assemble()`，避免双重记账冲突。

修复后收敛：

```
0: compress_2   compressed=True   msgs=6  记账=[75]
1: compress_1   compressed=False  msgs=6  记账=[50, 75]
2: session_end  compressed=False  msgs=6  记账=[50, 75]
```
