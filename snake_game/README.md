# 终端贪吃蛇（Python 标准库实现）

纯标准库、无第三方依赖，只用 `print` + ANSI 转义画整屏，固定时间步推进（不靠 `sleep` 决定速度，因此速度稳定、不受渲染耗时影响）。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `config.py` | 全部常量：棋盘尺寸、速度参数、渲染字符、ANSI 颜色、按键映射。无逻辑无副作用 |
| `game.py` | 纯逻辑层：状态、规则、推进。**不导入**终端/键盘/时间库，也不打印任何东西，可被无头工具直接调用 |
| `main.py` | 入口：参数解析、非阻塞读键、固定时间步主循环、整屏重绘 |
| `README.md` | 本文件 |

中立 API 契约（`game.SnakeGame`，请勿改名）：`__init__(width, height, seed)` / `move(direction)` / `step()` /
属性 `score` / `snake` / `food` / `over`（另有 `won` / `direction` / `steps_per_sec` / `frame_interval`）。

## 启动命令

在仓库根目录（`snake_game/` 的上一层）执行：

```bash
# 推荐：包方式运行
python -m snake_game.main

# 脚本方式运行（内部会自动把父目录加入 sys.path）
python snake_game/main.py
```

常用参数：

```bash
python -m snake_game.main --width 30 --height 20   # 改棋盘尺寸（最小 6x6）
python -m snake_game.main --seed 7                 # 固定随机种子，食物序列可复现
python -m snake_game.main --no-color                # 关闭 ANSI 颜色，适合日志/录屏
python -m snake_game.main --headless 200            # 无头自检：随机转向跑 200 步后退出
```

> 当 `stdin` 不是终端（例如被自检工具重定向）时，程序会自动切到无头模式并打印提示，避免在管道里死等按键。

## 按键

| 按键 | 作用 |
| --- | --- |
| `W` `A` `S` `D` 或 ↑ ↓ ← → | 上 / 左 / 下 / 右 |
| `P` | 暂停 / 继续 |
| `R` | 重开一局 |
| `Q` | 退出 |

- 反向输入（如正向右时按左）会被**静默忽略**，不报错也不自杀。
- 一帧内连按多个方向**不会互相覆盖**，而是进入待执行队列按序生效，详见下一节「方向缓冲」。
- `Ctrl+C` 可随时中断，退出时会恢复光标显示。

## 方向缓冲

`move(direction)` 并不直接改写当前方向，而是把合法方向压入**待执行队列**；`step()` 每帧只从队首取出一个方向执行，队列空时维持原方向。因此一帧内连按两次不会丢输入——「先上再左」这种连续折返能完整生效。

- **容量**：`DIRECTION_QUEUE_SIZE = 2`（见 `game.py`）。最多积压 2 个待执行方向，会在接下来的 2 帧内依次生效。
- **判重基准是队尾**，不是当前方向：队列为空时以当前方向为基准，非空时以队列最后一个方向为基准。
- **按序生效**：`step()` 每次 `pop(0)` 消费队首一个，先按的先执行，不会调换顺序。
- **丢弃规则**（以下情况静默忽略：不抛错、不入队、不改变已有队列）：
  1. 与基准方向（队尾，空则当前方向）**相同** —— 重复按键无效；
  2. 与基准方向**相反**（如队尾为 `right` 时按 `left`）—— 禁止 180° 自杀，且仅在蛇长 > 1 时判定；
  3. **队列已满**（已有 `DIRECTION_QUEUE_SIZE` 个待执行方向）—— 多余输入直接丢弃。
- **唯一会报错的路径**：传入不在 `up / down / left / right` 之中的方向字符串，抛 `ValueError`。
- 游戏结束后 `move()` 立即返回，不再入队（状态冻结）。

举例：蛇正向右移动时连按「上」「左」，队列变为 `[up, left]`；接下来两帧依次向上、向左。若连按「上」「下」，第二次因与队尾 `up` 相反而被丢弃。

## 计分与加速规则

- 吃到 1 个食物：`score += 1`，蛇身长度 `+1`，尾部不收缩；食物立刻在**空格中**重新随机生成（不会刷在蛇身上）。
- 未吃食物时：头进一格、尾退一格（因此"追自己的尾巴"是合法的，尾格不算碰撞）。
- 速度（固定时间步）：

  ```
  steps_per_sec = min(INITIAL_SPS + SPS_PER_FOOD * score, MAX_SPS)
                = min(10.0 + 0.6 * score, 22.0)
  ```

  即初始 10 步/秒，每吃 1 个 +0.6 步/秒，**score = 20 时达到 22 步/秒上限**，之后不再加速。
  一帧时长 `frame_interval = 1 / steps_per_sec`，主循环用累加器 `acc` 消耗时间，保证帧率与渲染速度解耦。
- 结束条件：
  - 撞墙（头部越界）或撞到自身（吃食物的那一帧尾巴不动，故尾巴也在碰撞判定内）→ 游戏结束，`over = True`。
  - 蛇填满整个棋盘、无处生成食物 → `won = True`，`over = True`，界面显示通关祝贺。
- 结束后 `step()` / `move()` 变为空操作，状态冻结，直到按 `R` 重开。

## 已知限制

1. **无头自检的 `score` 常为 0 是正常现象，不是缺陷。** `--headless` 用随机方向驱动，默认开局向右，蛇头从 x=10 出发，10 步内就撞到右墙；此后 `step()` 空转，所以 `frames=200` 而 `score=0`、`length=3`。这是"状态冻结"契约的体现。
2. **没有 `__init__.py`**，靠 Python 3 的隐式命名空间包被导入。因此在 `snake_game/` 内部直接 `python game.py` 无法相对导入；必须在父目录用 `-m` 或脚本方式启动。
3. **读键以 Windows 为主**（`msvcrt.getwch`）。POSIX 分支（`tty.setcbreak` + `select`）代码已写但**未在真实 POSIX 终端验证**，箭头键解析可能因转义序列分片而漏读。
4. **渲染依赖终端能力**：需要支持 ANSI 转义（Windows 10+ 控制台会尝试自动开启 VT，失败则静默退化为无色）；每格占 2 个字符宽（1 字符 + 1 空格），所以棋盘是"方块"而非正圆点，窄终端下会折行。窗口过小时不自动缩放。
5. **没有持久化**：不保存最高分、无排行榜、无回放/录像。
6. **无音效**、无鼠标支持。
7. **测试薄弱**：`config.py` / `game.py` / `main.py` 没有独立单元测试文件，目前只有外部工具的无头自检与 `--headless` 冒烟测试覆盖主路径。
8. **贪心策略不代表可解性**：6x6 小棋盘上朴素贪心会自陷而死；"填满棋盘获胜"只在很小棋盘 + 极好走位下可达，属理论路径。
